Architecture

How the CRM is built

Technical companion to the product plan · apa.com.au

1 · Overview

This is a Next.js (App Router) app deployed on Vercel, backed by a Supabase Postgres database, with Resend for email. It has two surfaces: a public marketing site that captures leads, and an /admin CRM. /admin starts open and unprotected, and gets locked down with email-and-password Supabase Auth later in the build.

2 · How the pieces fit

Next.js (App Router)

Renders the public marketing site and /admin. Server code handles form submissions and all database reads and writes — the browser never talks to the database directly.

Vercel

Hosts and deploys the app. Environment variables hold every secret. A git push deploys — no manual deploy commands.

Supabase (Postgres)

The database. Accessed server-side only, using the service key. Secrets never reach the browser.

Resend

Sends the confirmation email when a lead comes in. Wired in Build 2, from the verified apa.com.au sending domain.

Environment variables

  • NEXT_PUBLIC_SUPABASE_URL — the Supabase project URL.
  • NEXT_PUBLIC_SUPABASE_ANON_KEY — the public anon key for safe client-side reads (used sparingly).
  • SUPABASE_SERVICE_ROLE_KEY — the server-only key for all privileged reads and writes. Never exposed to the browser.
  • RESEND_API_KEY — authorizes sending the confirmation email.
  • NEXT_PUBLIC_SITE_URL — the live domain (apa.com.au), used for email links and redirects.

3 · The lead flow — one inquiry end to end

  1. A visitor submits the contact form on apa.com.au.
  2. Server code upserts a People row by email — an existing person is updated, never duplicated.
  3. It creates a linked Contacts row in status new_lead, with the inquiry type, subject, and message.
  4. (Build 2) Resend sends a confirmation email from apa.com.au.
  5. The operator sees the lead in /admin and works it through the pipeline.
  6. Each status change writes one activity_log row — a permanent trail of who moved what, and when.

People One row per person, deduplicated by email.

Newsletter — not a table

Tracked by People.ok_to_contact = true. Everyone with that flag is on the list; there is no separate table.

5 · Relationships

  • One Person has many Contacts (inquiries).
  • One Contacts row has many activity_log rows (its status history).
  • One Person has many Orders.
